# 讲解页（lesson-page）

## 这个 skill 要解决什么

用户的原话（2026-11-19）：我给的信息“实在太多，并且是散着的”，是“散点的、网状的，不知道每一个点的出处”；活干完了，但他“完全没有学到东西，也无法监督到底是如何完成的”，“如果不知道你在干什么会很没有底气很害怕”。他读教材的感觉是“很通顺，很有逻辑的一条线，让我能跟着理解在干什么”。

所以讲解页成不成功，只看一件事：**读者读完，能不能用自己的话把这件事从头讲一遍，并且知道每一步为什么这样做、可以去哪里核对。** 页面再全、再准，读者跟不下来就是失败。

我的默认写法是“报告”：按我做事的结构组织，结论先行，面面俱到，并列的小节、大表、所有数字。这对查资料有用，对学习没用。讲解页是“一节课”，按读者怎样才能懂来组织。两者的差别：

| | 报告（不要） | 一节课（要） |
|---|---|---|
| 开头 | 总览流程图、要点列表 | 一个具体的场景和一个问题 |
| 顺序 | 按步骤 / 模块并列 | 一个问题的回答引出下一个问题 |
| 新东西 | 一次全摆出来 | 一次只加一个，用到时才引入 |
| 例子 | 每节换一个，或者没有 | 同一个真实例子从头用到尾 |
| 规则 | 先给规则 | 先看例子，再说规则，再说为什么 |
| 细节和数字 | 都在正文 | 主线只留必要的，其余折叠或放到后面 |
| 结尾 | 待办和问题清单 | 把整条线回顾一遍，再说现状 |

## 动笔之前：先定三样

不写下这三样就开始做页面，几乎一定会写回成报告。

1. **读者的起点**：他已经知道什么，哪些词对他是新的。宁可假设他忘了上次讲过的细节。
2. **一个主问题，最多三个“读完你能……”**：整页只回答这一个问题。答不完说明该拆成几课。
3. **主线：一串“问题 → 回答 → 新问题”**。写成 5–7 环的链，每一环一两句话。例如：
   - 模型每一步在回答什么？→ 七道选择题。可答案从哪来？
   - 答案 = 离目标还差多少。那目标是哪个位姿？
   - 抓的目标 = 夹住那一刻。怎么知道哪一帧夹住了？
   - 看夹爪信号。那是不是之前的每一帧都用？
   - 只取最后一小段。合起来看一遍 → 回顾。

   检查这条链：每一环是不是必需的？有没有哪一环用到了后面才讲的东西？能不能只读这条链就明白大意？链以外的内容，要么进“想看细节”的折叠，要么留到下一课，要么不写。**删掉比加上更重要**：读者被淹没，正是因为我舍不得删。

内容多的时候拆成几课，另做一个目录页，每一课标明它回答的问题和依赖哪一课。一课的量：读 8–12 分钟，约 1,500–2,500 字，5–8 张图。

## 一课的骨架

模板在 `assets/template.html`（样式都内联在里面），各组件的写法在 `references/components.md`。

1. **开头框**：这一课回答什么问题；读完你能……（最多三条）；大约几分钟；需要先知道什么。
2. **从一个具体场景开始**。不是定义，不是流程图。先让读者看见一个真实的东西。
3. **正文每一节是主线上的一环**：
   - 标题就是这一节要回答的问题。
   - 第一句接住上一节末尾留下的问题。
   - 先看例子（真实数据的图），再说规则，再说**为什么这样做**（最好用“不这样做会怎样”来说，有反例更好）。
   - 一节只引入一个新概念。新名词第一次出现时加粗、当场用一句话解释，之后不换说法。
   - 结尾用一两句话小结“到这里我们知道了什么”，并提出下一节的问题。
   - 可以放一个“想一想”：一个读者此刻能答出来的小问题，答案折叠起来。它的作用是让读者停一下、确认自己真的懂了，不是考试。
4. **回顾**：把整条线画成一张小图。这时读者认识图上的每一个框，流程图才有用。再用三五句话总结，并分清哪些来自数据、哪些是规则、哪些是模型或人的判断。
5. **现状**（讲的是正在做的事时才需要）：做了什么、没做什么、哪里拿不准、需要读者定什么。每类最多三条。
6. **这一课没讲什么**，以及下一课的问题。
7. **附：出处、名词、去哪里核对**。

## 写法

- **一次只讲一件事。** 人一次只能拿住三四样新东西。一段里出现三个括号、两个新名词，读者就掉线了。
- **先具体后抽象。** 例子在前，规则在后。读者有了画面，规则才挂得住。
- **一个例子用到底。** 选最简单、但是真实的那个；整课的图都来自它。确实要换例子时，先说为什么换。
- **数字要克制。** 主线上只放会改变结论的数字，并且说清分母和量法（“350 条示范里的 829 次抓取，中位数 1.0 秒”）。其余进折叠。
- **每个说法都有出处。** 用户明确说过“不知道每一个点的出处”。出处只有五种，用页面上的小标记标在说法后面，文末汇总成表：
  - 实测：我量出来的。写明在什么数据上、多少样本。
  - 你定的：用户的决定。写明日期。
  - 我的判断：我的建议或推断，没有验证过。
  - 文献：哪篇文章的哪一节。没核对过原文就不要写章节号。
  - 代码：哪个文件的哪个函数。文件名、函数名只出现在这里，不进主线正文。
- **不确定就说不确定**，在它出现的地方说一次，不要到处加保留语气。
- **图承担讲解，不是装饰。**
  - 一张图只说一件事，放在讲到它的地方。
  - 要看哪里，直接标在图上；图注用一句话说“从这张图能看出什么”。
  - 讲数据和过程用真实数据画的图；讲概念用示意图。
  - 检验办法：把图删掉，正文如果照样通顺，说明这张图没在干活。
- **提示词原文、伪代码、大表默认折叠。** 主线用人话讲它在做什么；想核对的读者自己展开。
- **不要出现**：一上来的大流程图；并列的长列表；“你 11 月 17 日说……后来又改成……”这类沿革（只讲现在的做法，沿革进出处表）；代码标识符；一句话里的多重限定。

## 页面形式和放在哪里

- 单栏，正文宽约 720 px，字号 17 px 左右，行距宽松。左侧（窄屏在顶部）有一条“进度”，列出各节的问题并标出读到哪里：读者随时知道自己在整条线的什么位置。
- 自包含：样式内联，不用外部字体和 CDN，图片用相对路径。
- 源文件放在项目里：`<项目>/docs/lessons/<主题>/`，里面是 `index.html`（或目录页加 `01-….html`）和 `fig/`。图由脚本从真实数据生成，脚本放进项目的 `scripts/`，保证能重跑。
- 项目有本地站点就接进去；没有就在 `127.0.0.1` 上起一个静态服务。给用户完整的链接。

## 做的顺序

1. **自己先搞懂。** 读代码、数据、以前的页面，直到能不看材料把主线讲出来。讲不出来就不要开始写。
2. **写主线链**（上面的第 3 样），自己检查一遍。
3. **选例子，准备图。** 先确定每张图要说的那一件事，再去画。
4. **写页面**：复制 `assets/template.html`，按骨架填。
5. **当一回读者。** 用 `scripts/shot.py` 给页面截整页图，从头到尾看一遍；再对照 `references/checklist.md`。排版是否重叠、图上的字能否看清，只有看了截图才知道。
6. **交给用户。** 聊天里只写：链接、这一课回答什么问题、希望他重点看哪里，五行以内。不要把页面内容在聊天里再讲一遍。
7. **收到反馈后**：改页面；能推广的教训写回本文件，并在 `references/iterations.md` 记一笔（哪天、用户说了什么、改了什么）。只对这一页有效的修改不要写进 skill。

## 讲解页之外

用了这个 skill 的那一轮，聊天回复本身也按同样的精神写：先说结论，只讲一件事，不堆并列要点。
