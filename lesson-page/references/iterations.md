# 迭代记录

每次用户对讲解页提意见后记一笔：哪天、原话或要点、改了页面的什么、有没有写回 SKILL.md。
能推广的教训写回 SKILL.md 或 components.md；只对某一页有效的修改只记在这里。

## 记录格式

- YYYY-MM-DD　用户说了什么（原话或要点）→ 改了页面的什么 → 有没有写回 skill（写到了哪个文件）。

## 已经写回 skill 的几条经验

- 交出去之前一定看截图：图上的字压线、超出方框、被截断，只看代码发现不了。
- 同一组答案在几个时刻的变化要做成对齐的网格；同一张图一节加一层；对比两种做法时只让不同的那一格显眼（见 components.md）。
- 一课中途换例子时，先用一句话说明为什么换。
- “现状”类的课也能写成一条线：哪一步会出错 → 怎么发现 → 要花多少 → 所以接下来。
- 讲的做法还在变的时候，先在课程目录顶部写明“哪些改动还没写进哪几课”，等定下来再一次改写受影响的小节。
- 讲别人的模型或论文时：在自己的一条数据上真跑一次，把每一步的输入、提示词、原始输出录下来当例子；论文的说法回原文逐条核对原句和章节号，核对不到的写“论文没有写”，自己的解释标成“我的判断”。
